Rule: Python calls special methods, you don't. Write len(x), never x.__len__().

Why len() is fast for built-in types

  1. Python itself is written in C. The standard Python you run is called CPython. Every Python object, such as a list, is a block of memory laid out as a C struct: a fixed record with named fields.
  2. Lists, strings and other collections whose size can change all start with the same struct, PyVarObject. One of its fields, ob_size, holds the current number of items. The list updates it on every append or pop, so len(my_list) just reads that field.
  3. Your own class takes the slow route. For len(deck), Python has to find __len__ on the class, set up a Python function call, and run your code, which here calls len() on the inner list. Same answer, several extra steps.
# a list in memory (simplified)
list object
├── ob_refcnt
├── ob_type   = list
├── ob_size  = 1000 ← len() reads
└── ob_item  → [items...]

# 5 million calls each (measured)
len(list)    0.09s

This is why len is a function, not a method: one syntax for everything, with a fast path for built-ins.

__repr__ vs __str__

__repr__ is for developers: it should show exactly what the object is, ideally looking like the code that recreates it. __str__ is for end users: it just has to be readable. print() calls str(), which uses __str__; if a class has no __str__, it uses __repr__ instead. So if you write only one, write __repr__.

>>> repr(d)

>>> str(d)

>>> print(repr("42"), repr(42))

That's why the chapter's Vector uses !r: f"Vector({self.x!r}, {self.y!r})".

Truthiness: bool(x)

bool(), if x: and while x: check, in order:

  1. __bool__, if defined: use its result (it must return an actual bool).
  2. Otherwise __len__: falsy if it returns 0.
  3. Otherwise: always truthy.

So a collection with only __len__ is falsy when empty, like [] and "".

# Vector: falsy only for Vector(0, 0)
def __bool__(self):
    return bool(abs(self))

# faster: skips the square root
def __bool__(self):
    return bool(self.x or self.y)
# `or` returns an operand (e.g. 3), not
# a bool: hence the bool(...) wrapper.
# bool(3) runs int's __bool__, not
# Vector's: no recursion.

The Collection API

Collection combines Iterable (__iter__), Sized (__len__) and Container (__contains__) by multiple inheritance: class Collection(Sized, Iterable, Container). Together these define what a collection is: something you can loop over, measure and search. The three main kinds, Sequence, Mapping and Set, are each a Collection with extra methods of their own. The ABCs (abstract base classes, in collections.abc) mark the core methods as required and provide the rest for free, built from those.

from collections.abc import Sequence

class Playlist(Sequence):
    def __init__(self, songs):
        self._songs = list(songs)
    def __getitem__(self, i):     # required
        return self._songs[i]
    def __len__(self):            # required
        return len(self._songs)

p = Playlist(["a", "b", "a"])
p.count("a")       # 2      free
p.index("b")       # 1      free
"b" in p           # True   free
list(reversed(p))  #        free

Reading the book's diagram (Figure 1-2): arrows mean "inherits from". Italic methods are abstract: you must write them. Plain ones are concrete: inherited for free.

Leave out a required method and Python refuses:

TypeError: Can't instantiate abstract class
Bad without an implementation for
abstract method '__getitem__'

FrenchDeck doesn't inherit from Sequence, yet in, for and reversed still work through Python's fallbacks to __getitem__. Inheriting adds index/count and makes isinstance(deck, Sequence) True.
